# Obsidian-сетап BRAIn Lab

Воспроизводимая конфигурация рабочего стола Андрея на **10-09-2026**: Border 1.13.6, Operon 3.0.1, доски «Мои задачи» и «Чтение», 14 включённых плагинов, три CSS-сниппета и проектные заметки. Внутри только настройки и вымышленные примеры. Плагины скачиваются из публичных релизов авторов в закреплённых версиях; SHA-256 проверяется до установки.

## Установить с нуля

1. Установите [Obsidian](https://obsidian.md/download) и [Python 3.10 или новее](https://www.python.org/downloads/).
2. Установите Git и получите набор из репозитория:

```bash
git clone --depth 1 --branch codex/obsidian-setup https://github.com/Vepricov/claude-brainlab.git
cd claude-brainlab/obsidian-setup
```

Набор опубликован в ветке `codex/obsidian-setup`. Если репозиторий уже клонирован, откройте эту ветку в отдельном чистом checkout, не сбрасывая свои изменения. Без Git можно использовать GitHub → Code → Download ZIP для этой же ветки.

3. Выберите **новое имя папки**, которой ещё нет. Выполните:

```bash
python3 install.py --vault "$HOME/My Research" --owner "Researcher"
```

В Windows PowerShell:

```powershell
py -3 -m pip install tzdata
py -3 install.py --vault "$env:USERPROFILE\My Research" --owner "Researcher"
```

`tzdata` даёт Python на Windows базу часовых поясов для дат Hermes. На macOS и Linux используется системная база.

Вместо `Researcher` укажите имя, под которым будут создаваться ваши задачи. Установщик откажется менять существующий vault. Он готовит всё во временной папке и переносит результат только после проверок. При обрыве скачивания новый vault не появляется; команду можно повторить.

4. В Obsidian выберите **Open folder as vault / Открыть папку как хранилище** и укажите созданную папку. Разрешите community plugins для этого vault. При необходимости перезапустите только это окно Obsidian.
5. Откройте `START HERE.md`. Рабочее пространство «Старт» восстановит две доски, Calendar и `general/todo.md`. Если оно не открылось автоматически: палитра команд → Workspaces → Load workspace → «Старт».

Интерфейс Obsidian можно переключить на русский в настройках. Статусы досок уже русские. Mac/Windows/Linux используют одинаковые файлы vault. На мобильном Obsidian Zotero Integration недоступен: этот плагин предназначен для настольной версии.

## Что получится

- **«Мои задачи»**: Надо → Делаю → Передал на проверку → Готово.
- **«Чтение»**: _Trash → Жду публикацию → Инбокс → Очередь → Читаю → Прочитано. Пустые колонки компактные, остальные делят доступную ширину.
- **Dashboard**: таблица Operon, ссылки на пример проекта и его доску Hermes.
- **Проекты**: собственные папки в `Papers/`, `Projects/` или `Staff/`; исходные материалы, решения и результаты остаются рядом.
- **Внешний вид**: Border, акцент, размеры, компактные строки и служебные ссылки как в эталонной конфигурации. Цвета конкретных личных проектов удалены.

Файловые задачи Operon содержат короткий `operonId`, статус, приоритет и исполнителя. Inline-задачи хранят те же поля в строке Markdown. Демо-карточки можно удалить после знакомства. Не добавляйте `operonId` к обзору Hermes: это отдельная очередь, которую вы только читаете.

## Что отличается от чистых релизов

В `patches/` лежат небольшие правки отображения из эталонной конфигурации: Operon 3.0.1 и даты Tasks 7.23.1. Они применяются только к точному SHA-256 исходного `main.js`, а результат проверяется повторно. Названия/цвета/статусы данных от этого не изменяются. Для обычного вида авторских релизов установите с `--upstream-display`.

Обновление плагина заменяет его `main.js`. Не применяйте старую правку к другой версии. Сначала проверьте новый релиз в отдельном vault. Тема Border поставляется исходным CSS с MIT-лицензией. Для производных правок Operon сохранена GPL-3.0, для Tasks — MIT; ссылки на исходники и лицензии находятся в `THIRD-PARTY.txt`.

## Hermes: личная доска внутри проекта

```text
Hermes выполняет работу
    ↓ пишет задачи, комментарии, результаты
kanban.db на вашем сервере
    ↓ SQLite read-only через ваш SSH
sync_hermes.py — детерминированный Python
    ↓ раз в минуту по системному расписанию
Papers/<project>/Knowledge/Hermes/
    Доска.md       активные карточки
    История.md     завершённое и архив
    snapshot.json исходный снимок
```

Агент продолжает управлять своей исходной доской. Экспортёр сохраняет **тот же task ID и статус**. На карточке видны приоритет, исполнитель, даты, контекст, результат, последние сообщения о сервере/GPU и причина ожидания, если Hermes её записал. При отсутствии сведений они так и помечаются. Новый снимок не делает старое сообщение о GPU актуальным мониторингом.

Обзор открывается в режиме чтения Obsidian без Canvas и без плагина канбана. Нажмите карточку, чтобы раскрыть подробности. Собственные комментарии храните рядом отдельной заметкой: экспортёр останавливается, если сгенерированный файл был изменён вручную. При недоступном SSH предыдущий успешный снимок сохраняется. Работающий Hermes и работающий GPU-прогон — разные состояния.

Показанный контракт относится к нашему профилю Hermes с `kanban.db` и таблицами `tasks`, `task_comments`, `task_runs`, `task_events`. У чистой установки Hermes такой доски может не быть. Сначала узнайте у владельца профиля настоящий путь и board slug; не создавайте случайную базу для обхода ошибки. Проектная папка в Obsidian тоже должна уже существовать.

### Подключить свою доску

1. Настройте свой SSH alias и доступ на чтение нужной базы. Python 3 нужен локально и на сервере; удалённый SQLite читается с `mode=ro`. Пароль или ключ в конфигурационный JSON не записывается.
2. Скопируйте `examples/hermes-config.json` за пределы публичного репозитория. Заполните абсолютный путь к vault, SSH alias, корень с каталогами досок и соответствие **существующий slug → собственная папка проекта**.
3. Сделайте один проверочный запуск:

```bash
python3 sync_hermes.py --config /absolute/path/to/hermes-config.json
```

Например, запись `"optimizer": "Papers/optimizer"` ведёт только в `Papers/optimizer/Knowledge/Hermes`. Несколько существующих досок можно перечислить в одном `projects`. Завершение задачи не подтверждает научное утверждение: для него агент отдельно сохраняет основания и оценку в Lab Knowledge MCP.

Для проверки без сервера создайте конфиг с путём к тестовому vault и демонстрационным проектом, затем:

```bash
python3 sync_hermes.py --config /absolute/path/to/test-config.json --snapshot examples/hermes-snapshot.json
```

В примере нет реальных исследований. Его время намеренно фиксировано, и фоновое обновление не включено.

### Автоматическое обновление

На Mac используется **launchd раз в 15 минут**, пока компьютер включён и доступен сервер. В этом цикле нет LLM, Codex-tick или Operon. Скопируйте `schedules/com.lab-atlas.hermes-obsidian.plist` в `~/Library/LaunchAgents/`, заменив три абсолютных пути: Python, скрипт и конфиг. Затем:

```bash
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/com.lab-atlas.hermes-obsidian.plist"
launchctl print "gui/$(id -u)/com.lab-atlas.hermes-obsidian"
```

На Linux замените абсолютные пути в `schedules/lab-atlas-hermes.service`, скопируйте этот файл и `lab-atlas-hermes.timer` в `~/.config/systemd/user/` (создайте каталог при необходимости). Выполните `systemctl --user daemon-reload`, затем `systemctl --user enable --now lab-atlas-hermes.timer`. Проверка: `systemctl --user status lab-atlas-hermes.timer`; журнал: `journalctl --user -u lab-atlas-hermes.service`. На Windows создайте задачу в Task Scheduler: запуск `python.exe`, аргументы `"C:\path\sync_hermes.py" --config "C:\path\hermes-config.json"`, повтор раз в 15 минут, новая копия не запускается, пока предыдущая работает. Для путей с пробелами сохраняйте кавычки.

Проверьте, что дата `Обновлено` меняется, исходные task IDs совпадают, а при отключённом сервере остаётся прежний снимок. Если причина помощи или ресурсы не записаны в Hermes, исправьте исходное сообщение агента. Экспортёр их не придумывает. Обратной записи статусов из Obsidian в Hermes или Yonote в этом наборе нет.

## Установить в существующее хранилище

Автоматическое слияние здесь специально не предусмотрено: конфигурация Operon содержит ваши статусы и пресеты. Сначала установите набор в новый тестовый vault, сравните доски, затем перенесите выбранные настройки при закрытом целевом Obsidian с резервной копией. Не заменяйте целиком `.obsidian`, `data.json`, workspace или каталог задач. Автоархиватор задач в набор не включён и не запускается.

## Проверить результат

- Открываются обе доски и карточки, работает переключение в таблицу Dashboard.
- Новая задача получает ваш assignee, короткий operonId и статус выбранной доски.
- «Чтение» содержит демонстрационный Inbox; полный разбор статьи требует подключения агента.
- В примере проекта раскрываются карточки Hermes с датами и причиной ожидания.
- В `.lab-setup-receipt.json` записаны установленные файлы и их SHA-256.
