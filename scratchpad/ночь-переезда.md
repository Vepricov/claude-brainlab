# Ночь 30-09-2026: что сделано по переезду и что ждёт владельца

## Коротко

Развернуть GitLab не вышло, и это единственное, что не сдвинулось. Зато сняты все три
неизвестных, из-за которых переезд был рискованным: чтение из зеркал, раскол темы на
работы и проверки без сервера. Каждое проверено на живых данных, а не оценено.

## Чего не хватает: одна строка от владельца

Сервер лаборатории подходит по железу с огромным запасом (196 ГБ, 32 ядра, 668 ГБ), но
без docker и без sudo. Rootless разобран до конца: podman 6.1.2 поставлен в домашний
каталог, ядро готово (пространства имён включены, subuid выдан, cgroups v2), — упирается в
`newuidmap` из пакета `uidmap`. Это setuid-бинарь, без root его не поставить.

Нужно одно из двух, и первое предпочтительнее:

    sudo apt install uidmap          # даёт newuidmap, podman уже настроен
    sudo usermod -aG docker shkodnik1917   # равносильно root на машине

Машина туннеля не годится: 3 ГБ памяти против четырёх нужных, и на ней живут бот доступа и
публичное лицо базы. Ронять их ночью нельзя.

## Что проверено на живых данных

**Чтение из зеркал (шаг 3).** База, прочитанная из `git clone --mirror`, совпадает с
прочитанной из рабочих репозиториев по всем видам записей и по отпечатку веток:
расхождений ноль. Служба `lab-knowledge-mirror` держит 40 зеркал, проход раз в пять минут;
подхват и удаление ветки проверены в обе стороны. Пока GitLab нет, это заодно живая
резервная копия на 774 МБ.

**Раскол темы на работы (шаг 4).** Обычный `git subtree split -P <работа>`, история
сохраняется: 77 коммитов темы дали 35 и 3 у двух её работ. Никаких сторонних инструментов.

**Раскладка «работа = репозиторий».** Здесь я сам ошибся в документе: обещал, что читающая
часть не меняется. Это верно ровно пока тема — репозиторий. Правило переписано на оба
случая и проверено: обе раскладки дают одинаковые числа по работам, темам, утверждениям,
сериям, прогонам, измерениям, выкладкам и статьям.

**Проверки без сервера (шаг 8).** `ci_checks.py` считает те же проверки по рабочей копии:
изменённые файлы даёт git, тело предложения — переменная окружения. На живой ветке — ровно
те же девять замечаний, что даёт служба. После переезда вердикт будет появляться сразу, а
не через минуту.

**Клиент GitLab (шаг 4).** 525 строк, 33 теста на поддельном транспорте. Ответы GitLab
переводятся в форму, которую ждёт служба, чтобы вызывающий код не менялся.

**Словари (шаг 2).** Импортёр GitLab вики не переносит. `wiki_export.py` их выносит, и
разница между 208 страницами и 184 терминами разобрана до конца: 14 служебных, 5
не-терминов, 5 повторов имени. Проверять перенос по числу терминов, а не по коду возврата.

## Что нашлось попутно и было бы дорого потом

**`pr_checks` ходил мимо клиента.** Звал `_request("GET", "pulls/{n}/files")` и собирал
адрес архива Gitea руками. На GitLab это 404 — то есть подмена клиента сломала бы проверки,
не изменив в них ни строки. Обоим клиентам добавлено по два метода, проверки теперь зовут
только интерфейс. На живом pull request вердикт тот же.

**Литература в своём проекте.** У GitLab защита ветки не знает про пути, а правило
«литература правится без merge request» должно сохраниться. Поэтому литература выносится
отдельным проектом темы — это следствие, а не прихоть.

вчетверо плотнее прочих по утверждениям на работу (adapter-composition: 30 на 2) — похоже
на след прежнего прохода, стоит посмотреть.
