# BRAIn Lab Style Notes

`lab-style-mini.tex` — компактный визуальный референс. Это **стиль по умолчанию** для любой деки
этой лаборатории. Тёмный терминальный стиль — отдельная тема, включается только по явной просьбе.

Полное описание фирменного стиля и разбор грабель: Obsidian `general/Knowledge/brainlab-house-style.md`.

## Палитра

Два источника: постер `~/Papers/finished papers/kawasaki/poster/brainposter.sty` и лабовая дека
`~/Projects/huawei_optimizers/Talk3_Efficient_Pretraining_30min.pptx`. Дека главнее для слайдов,
и её схема такая:

| Роль | Имя | Значение |
| --- | --- | --- |
| Фон титула, разделов и финала; заголовки на креме | `plum` | `#854C65` сливовый |
| Фон контентных слайдов; текст на сливовом | `cream` | `#FAF8F1` кремовый |
| Заголовки на сливовом фоне | `amber` | `#FFD183` янтарный |
| Янтарный, читаемый на креме | `amberink` | `#A9741A` |
| Основной текст | `ink` | `#1F1B18` |
| Проблемы, ограничения | `red` | `#B0453F` |
| Подписи, второстепенное | `muted` | `#8C8078` |

**Белый фон не использовать.** Кремовый `#FAF8F1` вместо него: белый выглядит скучно и не
держится с остальной палитрой. Фигуры в белой карточке на кремовом фоне читаются как карточки,
и это работает в плюс.

Ритм деки строится на чередовании: полностраничные сливовые фреймы (титул, разделы, финал) и
кремовые контентные. Именно это чередование делает деку похожей на оформленную, а не на набор
слайдов. Для сливовых есть окружение `plumframe`.

Шрифт засечный (`lmodern`), НЕ монопространственный: монospace это терминальный стиль.

## Титул

- **Только типографика.** Ни логотипа, ни строки авторов, ни `$ run --...`: так сделана лабовая
  дека, и так лучше выглядит. Логотип оставить для постера и репозиториев.
- Крупное янтарное название (`\fontsize{40}{46}`), тонкая янтарная линия, кремовый подзаголовок.
- Внизу: дата слева, `BRAIn Lab` справа, обе янтарные.

## Разделители и финал

Тот же `plumframe`: маленький кремовый номер раздела, тонкая янтарная линия, крупный янтарный
заголовок. Финал: «Спасибо», линия, «Вопросы?».

## Заголовок контентного фрейма

Сливовый текст на кремовом плюс тонкая сливовая линия по **ширине текста**. Прогресс-бар темы
выключен (`progressbar=none`): он рисуется во всю ширину страницы, выглядит грубее и ломает
автопроверку вылезаний. Линия добавляется через `\addtobeamertemplate{frametitle}`.

## Боксы

- `mathbox` — белая карточка с тонкой сливовой рамкой: формулы, таблицы, нейтральное.
- `ideabox` — очень бледная сливовая заливка со сливовой полосой слева: идеи, выводы, результаты.
- `thmbox` — янтарная заливка: теоремы, устойчивые факты, неожиданные наблюдения.
- `probbox` — бледная красная заливка с красной полосой: проблемы, ограничения.
- `figcard` — белая карточка с тонкой сливовой рамкой вокруг фигуры.

Всем четырём нужен `fontupper=\small`, иначе три бокса не влезают в колонку.
Маркеры внутри бокса: `\good{...}` сливовый, `\bad{...}` красный, `\amb{...}` янтарный.
Подпись под фигурой `\fcap{...}` обязательно с `\par` внутри, иначе `\scriptsize` не управляет
межстрочным интервалом и подпись выглядит крупной.

## Фигуры: сначала искать, потом рисовать

**Готовые фигуры из статей всегда лучше самодельных схем.** Прежде чем генерировать что-то в
matplotlib, вытащить оригинал:

```bash
curl -sL https://arxiv.org/e-print/<id> -o src.tar.gz && mkdir -p <id> && tar xzf src.tar.gz -C <id>
find <id> -type f \( -iname '*.pdf' -o -iname '*.png' \)      # что вообще есть
grep -rhoE 'includegraphics\[[^]]*\]\{[^}]*\}' <id>/*.tex     # что реально используется в статье
```

Ещё до этого проверить `~/brainlab/*/*/literature/_attachments/<arxiv-id>/` — у части статей фигуры уже
извлечены скиллом `paper-ingest`.

Обрезать **только** `pdfcrop`, не самодельным `set_cropbox`: pdfTeX и pymupdf по-разному понимают
CropBox против MediaBox, и фигура вставится сдвинутой.

```bash
pdfcrop --margins 3 raw.pdf figures/paper-x.pdf
```

Чтобы взять одну панель из многопанельной фигуры: сначала сузить MediaBox, потом `pdfcrop`.
Портретную фигуру на 16:9 не втискивать целиком — вырезать из неё широкий фрагмент, который несёт
мысль.

Свои фигуры (когда готовой нет) — matplotlib, белый фон (фигура всё равно ляжет в белую карточку
на кремовом), засечный шрифт, `mathtext.fontset=cm`, линии цветами палитры: сливовый `#854C65`,
затемнённый янтарный `#C9A03A`, приглушённый синий `#5E8797`. Чистый `amber` `#FFD183` на белом
не читается, для линий брать затемнённый.

## Проверка вылезаний — обязательный шаг

Beamer **не предупреждает**, когда `tcolorbox` внутри `columns` вылезает за низ фрейма: содержимое
просто обрезается краем страницы, а `Overfull \vbox` в логе не появляется. Поэтому глазами это не
ловится, а `latexmk` рапортует успех.

Скрипт `scripts/check_overflow.py` рендерит каждую страницу, отбрасывает плашку заголовка и
прогресс-бар и смотрит, сколько чистого места осталось под содержимым:

```bash
python check_overflow.py deck.pdf     # нужен pymupdf + pillow + numpy
```

Здоровый слайд оставляет ~8.6 pt. `CUT` = содержимое режется, `tight` = на грани,
`WIDE` = таблица или фигура выходит за правый край.

Бюджет 16:9 на 10pt: тело фрейма ~205 pt (7.2 см). Практические ёмкости:

- колонка: фигура **или** три коротких бокса, но не то и другое;
- широкая фигура на всю ширину + максимум два бокса под ней;
- таблица на 9 строк — `\scriptsize` и явные `@{\hspace{9pt}}` между колонками.

Порядок исправления: сократить текст → убрать бокс → уменьшить фигуру → разбить фрейм.
`\small` для боксов уже стоит в стиле, дальше уменьшать шрифт не надо.

## Чего избегать

- Белого фона у контентных слайдов: только кремовый `#FAF8F1`.
- Тёмного фона, монопространственных заголовков, `// tag`, `$ run --...` — это терминальный стиль.
- Логотипа на титуле: там только типографика.
- Строки авторов и списка команд на титуле, если пользователь их не просил.
- `\cite{...}` в standalone-деке: хук `citation-validator` заблокирует запись. Использовать `\ax{}`.
- Самодельных схем там, где в статье есть готовая фигура.
- Стен из боксов без ни одной фигуры.
- Шести боксов на слайде: это гарантированный `CUT`.
