# Compatibility entrypoint: rebuttal composition

This filename is retained for legacy `rebuttal-writer` integrations. Generic fill-in-the-blank rebuttals are intentionally deprecated because they produce unsupported and repetitive prose.

Compose from the canonical concern ledger after grounding, theory audit, and experiment triage. Use the Draft Composer contract in `agent-prompts.md`:

1. answer the concern in the first sentence;
2. give only verified evidence with paper, derivation, citation, config, log, or table anchors;
3. state the exact paper change or experiment status;
4. disclose what remains unresolved.

Use one acknowledgment per reviewer thread at most. Cross-reference shared evidence without making another reviewer branch necessary for comprehension. Run every draft through `quality-gates.md` before release.
